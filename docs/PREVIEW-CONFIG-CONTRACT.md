# DataShelf 文件发现、配置与预览契约

状态：已接受，作为 MT-192 后续实现与验收的唯一跨层依据。

本文只定义行为和模块边界，不修改业务功能。若实现与本文冲突，以本文为准；若要扩大分享范围、放开 HTML 同源权限或增加新的配置值，必须另行做安全决策。

## 1. 现状与问题边界

仓库当前存在三种不同的新鲜度模型：

- `server.scanApps` 只在启动时扫描数据根，`server.apps` 因此看不到运行期间新增或删除的一级应用目录。
- `server.serveDirectory` 每次请求执行 `os.ReadDir`，普通目录内的新增、修改和删除本来就会在刷新后重新发现。
- `server.resolveDirectoryPolicy` 每次请求重读从数据根到目标目录的 `.env`，密码变化会通过策略版本使旧会话失效，没有长期授权缓存。

因此“刷新看不到新增目录”的根因是一级应用目录使用启动快照，并非页面缓存。后续实现不得用浏览器端猜测、定时 watcher 或延长陈旧快照寿命来掩盖它。

## 2. 文件与目录发现

### 2.1 请求时快照

服务端维护可并发读取的应用快照，但在每个会读取应用集合的请求入口重新构建并原子发布；GET/HEAD 刷新必须立即反映文件系统状态，认证 POST 等关联请求也不得消费启动时旧快照：

- 首页、应用路由、认证路由、受控预览/下载/HTML 路由和分享查找都消费本次请求取得的同一个快照。
- 扫描数据根时继续排除隐藏项、`a`、下划线开头名称、符号链接、非常规文件和非目录。
- 新增的合法一级目录在下一次刷新出现；删除或改名的目录在下一次刷新消失，旧 URL 返回 404。
- 同名目录被删除后重建时必须生成新的应用对象，不能沿用旧目录的配置状态、修改时间或其他可变字段。
- 根目录无法读取时返回 503，并记录结构化错误；不得回退到上一次成功快照，因为陈旧条目可能继续暴露已经撤下的目录。
- 单个条目在扫描与 `Lstat` 之间消失时跳过该条目；符号链接或类型变化一律按不可发布处理。

实现建议将 `apps map[string]*application` 改为受 `RWMutex` 保护的不可变快照，提供 `refreshApps() (map[string]*application, error)`。请求处理函数只使用局部快照，不在遍历期间读取可变全局 map。

### 2.2 子目录和文件

子目录列表保持请求时 `os.ReadDir`，不增加长期缓存。每一项仍必须通过 `DirEntry.Info` 和现有安全路径校验：

- 新增、修改、删除在下一次目录请求可见。
- 修改时间和大小来自本次请求，不复用上次渲染结果。
- `.env`、隐藏项、链接和非常规文件继续不可见。
- 目录读取失败不得显示旧列表，继续返回明确的访问错误页。

### 2.3 授权状态

不新增授权决策缓存。目录策略继续按请求从数据根折叠到目标目录；任一祖先 `.env` 读取或解析失败时锁定整个子树。应用删除、密码改变或安全选项改变后，下一请求不得继续使用旧策略。

## 3. `.env` 层级与密码

### 3.1 折叠顺序

配置按“数据根 → 应用根 → 当前目录的各级祖先 → 当前目录”折叠。字段分为两类：

| 字段 | 继承规则 | 说明 |
|---|---|---|
| `password` | 向下继承，最近的显式值覆盖 | 缺失表示继承，不提供用空值取消保护的语义 |
| `html_scripts` | 向下继承，最近的显式值覆盖 | 安全/行为选项 |
| `title` | 只描述 `.env` 所在目录，不向下继承 | 缺失时使用真实目录名 |
| `description` | 只描述 `.env` 所在目录，不向下继承 | 缺失时为空 |
| `SHARE_*` | 只作用于 `.env` 所在目录 | 分享不能从祖先隐式扩散 |

根与应用根保留现有大写旧字段的一次迁移兼容；嵌套目录只接受小写规范字段。旧字段与新字段不得混用。

任何已存在但非法、重复、未知、大小写近似、超限、非 UTF-8、链接或不可读的 `.env` 都锁定对应子树，绝不忽略错误后继承较弱策略。

### 3.2 密码值

`password` 接受以下两种规范输入：

- `hash:...`：已存储的版本化 Argon2id 哈希，只验证格式，不再次哈希。
- 无前缀非空值：首次设置的明文。读取时验证密码强度，使用现有原子比较并替换流程写回 `hash:...`，随后重读验证。

`plain:...` 仅作为兼容输入保留一个发布周期，处理结果与无前缀明文相同；文档和新示例不得再推荐 `plain:`。

边界规则：

- `password=''` 是配置错误并锁定子树，不能用它取消祖先密码。
- 明文只存在于读取、KDF 和原子迁移的最短路径中，不进入日志、模板、接口或分享状态。
- 原文件在迁移前发生变化时迁移失败并锁定本次请求，不覆盖并发修改。
- 策略版本包含整条祖先配置链和最终密码边界；祖先安全配置变化会使该子树旧会话在下一请求失效。

示例：

```dotenv
title='团队资料'
description='项目文档与演示'
password='首次设置密码123'
html_scripts='allow'
```

首次成功读取后 `password` 自动替换为 `hash:v1:argon2id:...`。

## 4. HTML、目录点击与源码预览

### 4.1 配置值

新增唯一配置键：

```dotenv
html_scripts='allow' # 默认值
```

合法值只有：

- `allow`：HTML 以隔离渲染模式执行脚本。
- `deny`：HTML 仍渲染，但禁止脚本。

缺失时默认为 `allow`，满足“默认可以直接输出”的产品要求。空值或其他值均锁定子树，避免拼写错误静默放宽或改变安全策略。

### 4.2 用户操作语义

| 操作 | 服务端能力 | 结果 |
|---|---|---|
| 点击目录名 | `OpenKind=directory` | 始终进入目录列表 |
| 目录内存在 `index.html` | 无特殊能力 | 不自动跳转，不覆盖目录列表 |
| 点击 `.html`/`.htm` 文件名 | `OpenKind=html-render` | 在新页面打开受控 HTML 渲染外壳 |
| 点击 HTML 的预览按钮 | `PreviewKind=text` | 在弹窗中以 `text/plain` 显示源码 |
| 点击其他可预览文件 | 既有 `PreviewKind` | 保持图片/PDF/文本/Markdown 预览行为 |

后端继续生成全部 URL 和能力字段，模板不得根据扩展名、DOM 或路径自行推断。需要删除 `serveApp` 中应用根检测 `index.html` 后自动跳转的分支。

### 4.3 HTML 安全模型

“直接输出”指按 HTML 解释并允许页面脚本运行，不等于授予资料应用的同源权限。普通访问和分享访问都遵守：

- HTML 始终位于受控外壳的 iframe 中。
- iframe 永远不包含 `allow-same-origin`、`allow-top-navigation`、`allow-forms` 或弹窗权限。
- `html_scripts=allow` 时只增加 `allow-scripts`；`deny` 时 iframe 无 `allow-scripts`，响应 CSP 同时设置 `script-src 'none'`。
- 不论配置值，响应保持 `sandbox` CSP、`object-src 'none'`、`base-uri 'none'`、`form-action 'none'`、`frame-ancestors 'self'`、严格 `Permissions-Policy` 和 `Referrer-Policy: no-referrer`。
- 渲染端点不能访问或复用普通资料浏览 Cookie 的同源能力；`HttpOnly` 只是纵深防御，不是脚本隔离边界。
- HTML 源码预览继续固定为 `text/plain; charset=utf-8`，不能因为 `html_scripts=allow` 改成可执行内容。

为了让自包含页面正常工作，允许内联样式、内联脚本、`data:` 图片和 `blob:`；默认禁止外部网络、表单提交、顶层导航、跨域连接和嵌套框架。相对本地资源不在本次文件分享的授权范围内，见下一节。

## 5. 分享渲染

分享状态向页面暴露 `State`、`RequiresPassword`、`ExpiresAt` 和 `CanDownload`。当状态为 `available` 且当前目录策略已经授权时，还必须提供可操作的完整 `ShareURL`，供页面显示“打开分享”和“复制链接”；否则“分享已配置”仍然不可用，不能满足 MT-192。

完整分享 URL 中包含的随机 token 是交付给接收者的能力凭据，浏览器在复制链接时必然可见；它只能在所属目录授权后下发，不得写入日志、错误页、未授权响应或普通状态字段。页面和接口仍不得暴露独立 token、密码、哈希、本地路径、分享 ID 或其他管理配置。公开目录中的分享 URL 对当前访客可见，与该目录本身的访问级别一致；受保护目录必须先通过其密码边界。

分享入口按目标类型分流：

- Markdown：认证后直接进入服务端安全渲染结果，不先显示源码。
- HTML：认证后直接进入与普通访问相同的 HTML 渲染外壳，并消费目标目录继承得到的 `html_scripts`。
- 图片/PDF/文本：进入既有预览。
- 不可预览类型：只有 `ALLOW_DOWNLOAD=true` 时提供下载。

页面只消费服务端生成的 `ShareURL`，不得从文件路径、DOM 或 `SHARE_*` 配置自行拼接 token 路由。

当前 `SHARE_*_SCOPE='file'` 只授权目标文件。HTML 中引用的同目录 CSS、JS、图片或其他文件不得因为一个文件分享而隐式获得访问权，相关请求返回 404。自包含 HTML 的内联脚本和样式可正常工作；若未来需要分享完整站点资源，必须新增显式的目录级分享范围并单独评审，不能在本次实现中扩大 `file` 的含义。

普通 HTML 渲染可以在应用授权边界内提供相对静态资源，但资源路由必须：

- 复用目标文件所在目录的策略授权；
- 逐段拒绝私有名、链接和非常规文件；
- 对 HTML 导航仍回到渲染外壳，不能裸露同源可执行响应；
- 对脚本、样式、图片和字体设置 `nosniff` 与准确 Content-Type；
- 不允许越过应用根或当前授权边界。

## 6. 静态脚本与样式缓存

将模板中的共享 CSS 和 JavaScript 分离为内嵌构建资源，例如：

```text
web/pages.tmpl
web/assets/app.css
web/assets/app.js
```

二进制仍通过 `go:embed` 自包含，不增加运行时目录依赖。构建时按内容摘要生成 URL：

```text
/_assets/app.<sha256-prefix>.css
/_assets/app.<sha256-prefix>.js
```

缓存契约：

- 指纹资源：`Cache-Control: public, max-age=31536000, immutable`，并返回基于完整内容摘要的强 ETag。
- 页面 HTML：公开页面 `Cache-Control: no-cache`；受保护页面、登录页、分享页和所有受控内容继续 `private, no-store`。
- 资源 URL 只由服务端模板数据生成，客户端不拼版本号。
- 二进制更新改变内容摘要和 URL，浏览器自然获取新资源；不得要求用户清缓存。
- 未命中或摘要不匹配的资源路径返回 404，不回退到“最新版本”。

静态资源不得包含租户数据、目录名、令牌或运行时配置，因此可以公开长缓存。

## 7. 实现归属

### 7.1 服务端

主要文件与责任：

- `server.go`
  - 应用快照的请求时刷新、并发发布和 503/404 行为；
  - 删除 `index.html` 自动跳转；
  - 生成 `OpenKind`、`PreviewKind`、渲染/源码/下载 URL；
  - HTML 普通访问、分享访问和静态资源路由；
  - 页面与指纹资源缓存头。
- `policy.go`
  - `html_scripts` 的祖先折叠、显式覆盖和策略版本；
  - HTML/分享请求复用同一目录授权边界。
- `config.go`
  - 接受无前缀首次密码并原子迁移；
  - 校验 `html_scripts=allow|deny`；
  - 保持分享状态无凭据输出。
- `security.go`
  - 原有应用 Cookie 路径和策略版本验证；若增加资源路由，只复用现有会话，不扩大 Cookie Path。

服务端对模板提供的跨层字段保持现有命名；如需补充，只允许增加明确布尔能力，不能下发原始 `.env` 值。推荐增加 `HTMLScriptsAllowed bool` 到渲染外壳数据，而不是让前端读取配置字符串。

### 7.2 页面层

主要文件与责任：

- `web/pages.tmpl`：保留语义化模板和服务端能力消费；目录点击、HTML 打开、源码预览不得自行推断。
- `web/assets/app.css`：承接共享布局、弹窗、图片适配、登录按钮、提示区和页脚样式。
- `web/assets/app.js`：承接主题、预览、图片缩放/适应、焦点管理；不得解析本地路径或扩展名来提升能力。

页面层不决定密码继承、HTML 脚本权限、分享范围、资源 MIME 或缓存头。

### 7.3 跨层共同验收

以下内容不能只由单层自行定义：

- `directoryItem` 的 `OpenKind`/`PreviewKind`/URL 组合；
- `html_scripts` 到 iframe sandbox/CSP 的映射；
- 分享目标类型到首个落地页面的映射；
- 指纹 URL 与缓存头；
- 受保护目录标题/描述是否展示属于产品隐私策略，不得由模板临时决定。

MT-192 已明确要求受保护目录标题和描述正常显示。实现时可以输出 `title`/`description`，但仍不得输出密码状态细节、哈希、分享配置或本地路径。

## 8. 测试切入点

### 8.1 服务端单元/集成测试

- 服务启动后新增、删除、改名一级应用，下一次首页和路由请求得到新快照。
- 根扫描失败不返回陈旧应用；扫描与读取竞态不 panic、不越权。
- 普通子目录新增、修改、删除文件后，下一次目录请求的名称、大小和修改时间更新。
- 祖先 `password`、`html_scripts` 向下继承，子目录显式覆盖；非法值锁定子树。
- 无前缀密码迁移为哈希；`hash:` 不改写；`plain:` 兼容迁移；空值和弱密码失败且不覆盖原文件。
- 任一祖先安全配置变化使旧会话失效。
- 含 `index.html` 的目录仍输出目录列表；点击 HTML 跳转渲染外壳，预览端点返回源码文本。
- `allow` 模式含 `allow-scripts` 但不含 `allow-same-origin`；`deny` 模式不含 `allow-scripts` 且 CSP 禁止脚本。
- 普通 HTML 相对资源不能越过应用根或授权边界；文件分享不能读取相邻资源。
- Markdown/HTML 分享认证后分别落到渲染结果；过期、错误密码和关闭下载仍保持现有失败语义。
- 已授权目录中的有效分享显示可打开、可复制的 `ShareURL`；未授权、过期或无效分享不泄露 URL/token。
- 指纹资源的摘要、ETag、长缓存和 404；页面及受保护内容的缓存头。

### 8.2 模板与浏览器测试

- 模板只消费后端能力字段，HTML 文件名与预览按钮行为不同。
- 图片初始自适应和“适应”按钮使用同一 contain 算法，不把图片缩到异常小尺寸。
- 登录页主按钮与“返回资料架”不重叠，320px 宽度下居中并保持间距。
- 受保护目录在上级列表显示配置的标题和描述，同时不出现安全凭据。
- 提示文案使用独立提示区并与正文留出间距，页脚水平居中。
- 指纹脚本加载后，主题、键盘焦点、预览关闭和图片导航回归通过。

## 9. 明确不做

- 不使用文件 watcher 作为正确性来源；它最多只能作为未来性能优化。
- 不允许 HTML 获得 `allow-same-origin` 或访问资料应用会话权限。
- 不把文件级分享偷偷扩大为目录分享。
- 不缓存目录列表、授权结果或 `.env` 解析结果到下一请求。
- 不新增 JSON API；当前服务端渲染契约足以完成 MT-192。
